Q. Why is Constructor injection preferred over Field injection ? 
Immutability
Dependencies can be marked as final, ensuring they don't change throughout bean's lifecycle.
Null safety
Component cannot be constructed or instantiated without its mandatory dependencies.
Easier Unit Testing
We can instantiate the class using a new Class(mockDependency) in plain unit tests without spinning up a heavy Spring Context.
Circular Dependency Detection
Constructor Injection triggers a BeanCurrentlyInCreationException at startup (Fail-fast), whereas field/setter injection might defer it to runtime.

Q. Difference between @Controller and @RestController ? 
@Controller: Used for traditional Spring MVC apps where methods typically return view names (like JSP or Thymeleaf templates).

@RestController: A specialized version of @Controller annotated with @ResponseBody. Every method automatically 
serializes return objects directly into JSON or XML and writes them straight into HTTP response body.

Q. How does @Transactional work, what is the most common pitfall ? 
How it works: 
Spring creates a dynamic proxy around the annotated bean. When a traditional method is called, the proxy intercepts the call, asks the 
PlatformTransactionManager to open a database connection, starts a transaction and commits/rollbacks based on runtime execution.

The "Self-Invocation Pitfall: If a method within the same class calls another @Transactional method internally (this.someMethod())
the proxy is bypassed entirely, and no transaction is created.
Fix: Inject a self-reference of the bean or refactor the method into a separate service class.
