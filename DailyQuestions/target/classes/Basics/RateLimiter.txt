protected void doFilterInternal(HttpServletRequest request,
				HttpServletResponse response,
  				FilterChain filterChain) throws ServletException, IOException {
	
 	1. Extract identification and tier headers (defaults to IP and FREE if missing)
        String userId = request.getHeader("X-User-Id"); 	
	if (userId == null || userId.isEmpty()) {
		userId = request.getRemoteAddr(); // Fallback to client IP
       	}
	
	String tierHeader = request.getHeader("X-User-Tier");
	UserTier tier;
	try {
	    tier = (tierHeader != null) ? UserTier.valueOf(tierHeader.toUpperCase()) : UserTier.FREE;
	} catch (IllegalArgumentException e) {
	    tier = UserTier.FREE; // Fallback tier
	}
	
	// 2. Validate against rate limiter
	Boolean isAllowed = rateLimiterService.allowRequest(userId, tier);

	if (!isAllowed) {
		response.setStatus(429); 	// HTTP 429: Too many requests
		response.setContentType("application/json");
		response.getWriter().write("""
			{
			   "status": 429,
			   "error": "Rate Limit Exceeded",
			   "message": "You have exceeded your %s tier limit. Please upgrade or try again later."		
			)""".formatted(tier.name());
		}
		return;
	}
	
	// 3. Pass request down the filter chain, if allowed
	filterChain.doFilter(request, response);
}


Distributed Environment: Mention that a ConcurrentHashMap only works for a single server instance. In a clustered microservice setup, we would replace it with Redis using 
Redis atomic operations (like INCR and EXPIRE) or Lua scripts to prevent race conditions.

Algorithm Variation: If fixed windows experience traffic bursts at window boundaries 
(e.g 5 requests at 00:59 and 5 requests at 01:01), we can propose Sliding Window Log or Token Bucket algorithms for smoother throttling).
